# v0.7.0 unattended state machine

## Root cause

v0.6.4 verified checkpoint shape and hashes but did not freeze evaluator completeness or threshold semantics. It also mapped every `PAUSE_REQUIRED` checkpoint, plus external notification dead-letter, to a Goal-level wait. That coupled experiment failure, chain closure, transport delivery, and Goal blocking into one state.

## Transition changes

| Evidence/event | v0.6.4 | v0.7.0 |
|---|---|---|
| evaluator complete, threshold failed | could be `invalid/PAUSE_REQUIRED` | valid `negative`, then rollback/switch |
| evaluator missing/corrupt/indeterminate | `invalid/PAUSE_REQUIRED` → Goal wait | invalid experiment; bounded recovery continues |
| negative final discriminator | close chain, commonly await decision | close only that chain; follow frozen other/switch/rollback path |
| notification pending/dead-letter/corrupt | wait or business pause | transport-only; durable event is consumed on SessionStart |
| receipt written, CONTROL save interrupted | next wake refused overwrite | verify and reuse receipt, then roll CONTROL forward |
| repeated event/result | could repeat recovery work | duplicate no-op |
| recovery paths remain | no global proof | blocking is forbidden |
| all paths and global recovery exhausted | ad-hoc model decision | machine `blocking_proof.block_allowed=true` |

`WAITING_EXTERNAL_EVENT` pauses the lease clock and does not consume recovery budget. No-event activations are told to end rather than poll. Monitor services still own durable scheduling and exact-thread delivery; the controller never resubmits a consumed Job.

## Data compatibility

- `CONTROL.json` remains schema 1 with additive `checkpoint_history`, `continuation`, `recovery`, and `consumed_output_roots` fields.
- Active schema-v2 leases complete using result schema 2.
- New proposals/results use schema 3 and freeze `evaluation_contract`, controller-owned outcome mapping, recovery paths, and a write-once output root.
- New checkpoints are immutable receipts. `correct-checkpoint` appends a record that references the superseded checkpoint; it never edits history.
- Legacy v0.6.4 checkpoints remain readable but cannot be corrected because they lack an immutable lease/chain snapshot.

## Hard block boundary

A Goal may request user input only for objective/metric/material-scope/budget changes, irreversible or high-risk external actions, unavailable external inputs or credentials, explicit global stop lines, or proof that every safe path and the global recovery budget are exhausted. Routine local recovery remains autonomous in fast profile.
